== System foundation

[source,mermaid]
----

    libc -->|"syscall wrappers"| libapi
    libapi -->|"allocation/memory functions"| libc
    libc -->|"bundles"| musl
    libapi -->|"int 0x80 syscalls"| kernel

    kernel -.->|"ELF definitions from elf.h"| libc

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d
    class clients callers
----

The kernel links freestanding and uses shared headers from libapi. Its ELF loader
also uses libc's +elf.h+ definitions, without linking libc. Kernel code includes no
application headers. Static archives defer symbol resolution to their consumers;
libc supplies the math functions behind the empty compatibility libm archive.

[source,mermaid]
----
flowchart TB

    apps -->|"POSIX file operations"| libc
    apps -->|"direct filesystem API"| libapi
    libc -->|"wrappers"| libapi
    libapi -->|"syscalls"| vfs
    vfs -->|"built-in backend"| ramdisk
    vfs -->|"delegate requests & shared pages"| fat
    fat -->|"sector I/O"| storage

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d
    class apps callers
----

The VFS selects the mount's backend. FAT requests go to a userspace delegate;
ramdisk operations stay inside the kernel. The live system uses the ramdisk,
while an installed system mounts its selected FAT boot volume as root.
See <<filesystem#,Filesystem>> for the delegate contract and the next section
for the block-storage path.

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d

storagemanager administers disks and partitions, coordinates exclusive volume ownership
and dispatches filesystem control jobs. fatdriver serves FAT12/16/32 and formats
FAT32 volumes. libblockdevice accepts the announced driver endpoint; AHCI is the
block provider in this checkout. AHCI's PCI access and device registration are
shown in the device-discovery section.

== Device discovery and PCI

[source,mermaid]
----
flowchart TB
    clients(["Applications and hardware drivers"])
    devices["libdevice"]
    manager["devicemanager"]
    pci["libpci"]
    driver["pcidriver"]

    clients -->|"device registration and queries"| devices
    devices -->|"IPC"| manager
    clients -.->|"device topic"| manager
    clients -->|"PCI enumeration and configuration"| pci
    manager -->|"controller selection"| pci
    pci -->|"PCI IPC"| driver

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d
    class clients callers
----

Hardware drivers register their serving task and device ID through libdevice.
devicemanager publishes registrations on the replayable device topic.
libpci wraps pcidriver's protocol, whose shared C-compatible definitions live in
libapi. Kernel power code and acpidriver use that protocol directly.

----

ƒenster and the headless terminal initialize PS/2 input through libps2driver.
libinput decodes pipe data and loads keyboard layouts through libproperties.
The graphical terminal receives input through ƒenster.

=== Terminal sessions

[source,mermaid]
----

    apps -->|"terminal control helpers"| client
    client -->|"escape and control stream"| terminal

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d

Terminal programs use inherited stdio; terminal-specific helpers add cursor,
input-mode and control operations over that stream. terminal starts gsh with
redirected descriptors. Its graphical frontend uses libfenster; its headless
frontend uses the input pipeline above.

Power coordination uses the PCI/ACPI protocols defined in libapi. The current

(application). libacpi provides an information-query helper, although no current
production target explicitly links it. See <<power#,Shutdown and reboot>>.

The graphics link set is used by ƒenster, editor, navigator and terminal.
FreeType and libpng use zlib; Cairo and Pixman also use libc's math functions.
The installed Cairo script interpreter is a companion port with no project
consumer. Other bundled implementations are musl in libc, uACPI in acpidriver
and Duktape in the js interpreter.

    classDef callers fill:#f3f4f6,stroke:#718096,color:#172b3d

Platform services are pcidriver, acpidriver and ps2driver; storage services are
ahcidriver, storagemanager and fatdriver. Navigator launches user-selected programs.
terminal starts gsh, which launches commands and pipelines. Navigator can also
forward later invocations to the existing desktop instance. The Doom launcher
references an optional binary absent from the current source/build targets.
